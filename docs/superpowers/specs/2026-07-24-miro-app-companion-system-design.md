# 米露全 App 核心伙伴系统设计

## 1. 目标与范围

米露是贯穿主 App 的核心伙伴。第一阶段覆盖 Web 和 Android，让米露在主要页面中拥有符合场景的落点、移动、空闲动作和用户反馈，同时避免遮挡内容或干扰操作。

本阶段不包含：

- 登录、注册和首次引导中的米露形象。
- iOS 专项适配。
- 完全自由寻路、实时碰撞或复杂避障。
- 拖拽米露。
- AI 自由决定动作。
- 自动声音、亲密度、等级、经验或养成系统。

## 2. 产品定位

米露采用“可控版自由活动”：

- 每个页面提供 2–4 个预设安全落点。
- 米露可以从页面边缘进场，也可以在当前页面的安全落点之间移动。
- 页面主体、输入框、导航栏和关键按钮属于禁入区域。
- 页面切换不等待米露完成退场；新页面立即可操作，米露随后自然走入默认落点。
- 用户可以轻触米露，触发短动作和一句性格化文案。
- 连续轻触具有冷却时间，不允许堆积动作或文案。

## 3. 第一阶段动作库

第一阶段包含 10 个动作：

| 类别 | 动作 | 用途 |
| --- | --- | --- |
| 基础状态 | 待机 | 默认姿势和动作间过渡 |
| 基础状态 | 坐下 | 倾听、等待和安静陪伴 |
| 基础状态 | 趴下 | 长时间阅读或停留 |
| 基础状态 | 睡觉 | 较长时间无操作 |
| 自主动作 | 舔爪 | 日常空闲动作 |
| 自主动作 | 回头观察 | 新事件、用户恢复操作 |
| 自主动作 | 伸懒腰 | 睡眠恢复、空闲变化 |
| 移动动作 | 走路 | 进场和落点切换 |
| 反馈动作 | 开心回应 | 点击、完成和成功事件 |
| 反馈动作 | 轻微难过 | 失败、取消等明确结果 |

所有动作默认无声。米露只在用户主动进入语音功能时使用现有语音能力。

## 4. 动作素材方案

以现有米露形象为唯一视觉基准，使用 AI 生成动作关键帧，再进行人工筛选和整理：

- 保持毛色、五官、体型、尾巴和整体画风一致。
- 所有动作使用统一画布、角色锚点、缩放比例和裁切边界。
- 清理透明边缘、残影、形变和不连续帧。
- Web 输出每个动作对应的透明精灵图。
- Android 输出经过压缩的透明帧序列。
- 美术素材尚未完成时，可以使用轻微位移、缩放和旋转制作开发占位，但占位素材不得进入正式验收。

## 5. 页面呈现设计

### 5.1 陪伴首页

- 米露是页面视觉中心，使用最大显示尺寸。
- 安全落点：中央、左下、右下。
- 主要动作：待机、走路、舔爪、伸懒腰、开心回应、睡觉。
- 轻触后播放开心回应并显示一句短文案。
- 这是第一阶段动作最丰富的页面。

### 5.2 聊天页

- 聊天顶部设置独立的小型陪伴区，展示完整米露。
- 米露不进入消息滚动区和输入区。
- 用户输入时坐下或回头观察。
- 等待回复时保持倾听姿势。
- 回复完成时播放开心回应。
- 用户表达负面状态时安静坐下或趴下，不使用夸张悲伤表达。

### 5.3 信箱页

- 米露位于信箱主体或列表侧边的安全区域。
- 进入页面时走到信箱旁。
- 有新信时回头观察。
- 打开信件后坐下陪伴。
- 长时间阅读时趴下。
- 不遮挡标题、未读标记和打开操作。

### 5.4 片场页

- 米露位于场景入口或舞台边缘。
- 进入页面时从边缘走入。
- 准备或生成内容时坐下等待。
- 生成成功时开心回应。
- 失败时轻微难过，然后恢复待机。
- 不进入场景预览和主要编辑控件。

### 5.5 “我的”页面

- 米露位于个人信息区域下方或设置列表上方。
- 主要动作：坐下、趴下、舔爪、睡觉。
- 设置保存成功后回头观察或开心回应。
- 米露不在设置列表之间移动。
- 这是动作密度最低的页面。

## 6. 行为触发规则

动作由用户行为和明确场景规则驱动，不由 AI 自由决定。

主要事件包括：

```text
PAGE_ENTER
PAGE_LEAVE
USER_ACTIVE
USER_IDLE
PET_TAPPED
MESSAGE_TYPING
REPLY_RECEIVED
NEW_LETTER
TASK_SUCCEEDED
TASK_FAILED
APP_BACKGROUND
APP_FOREGROUND
```

主要规则：

- 页面进入：从边缘走到默认落点。
- 页面停留：每隔 12–25 秒，从当前页面允许的集合中随机选择一次短动作。
- 轻触米露：播放短回应动作和一句性格化文案，然后进入冷却。
- 明确成功事件：开心回应。
- 明确失败或取消：轻微难过或安静坐下。
- 较长时间无操作：从坐下逐步切换到趴下或睡觉。
- 用户恢复操作：回头观察或伸懒腰，然后返回待机。
- 页面离开或 App 进入后台：立即停止动画和计时器。

## 7. 状态与优先级

核心行为状态：

```text
entering
idle
moving
acting
sleeping
paused
fallback
```

事件优先级从高到低为：

1. 页面离开、App 进入后台、减少动态效果。
2. 用户主动轻触和明确业务结果。
3. 页面进入与落点移动。
4. 长时间无操作。
5. 12–25 秒随机自主动作。

高优先级事件可以取消尚未开始的低优先级动作。除页面离开和 App 进入后台外，不粗暴打断正在播放的短动作；后续事件进入单项待处理槽，同类事件只保留最新一次，避免队列堆积。

## 8. 技术架构

### 8.1 素材注册层

登记每个动作的统一元数据：

- 动作 ID。
- Web 精灵图。
- Android 帧序列。
- 帧率和时长。
- 是否循环。
- 角色锚点和画布尺寸。
- 允许的结束姿势。

### 8.2 行为控制层

行为控制器负责：

- 接收页面和业务事件。
- 维护当前行为状态。
- 根据优先级、冷却和页面规则选择动作。
- 选择目标落点。
- 在动作完成后安排下一状态。
- 管理用户空闲和自主动作计时器。

### 8.3 页面场景层

每个页面只声明：

- 页面场景 ID。
- 默认落点和其他安全落点。
- 禁入区域。
- 允许的自主动作。
- 页面事件到行为事件的映射。
- 显示尺寸和移动边界。

页面不直接操作动画帧，也不复制行为优先级逻辑。

### 8.4 平台渲染层

- Web：每个动作使用单张精灵图和 CSS 动画，不做逐帧 React 状态更新。
- Android：使用预加载的压缩透明帧序列。
- 两端共用动作名称、状态机、页面事件和动作选择规则。
- 平台层只负责资源加载、播放、结束回调和失败上报。

## 9. 数据流

```text
页面/业务事件
  → 页面场景映射
  → 米露行为控制器
  → 动作与目标落点决策
  → Web 或 Android 渲染器
  → 动作结束/失败回调
  → 行为控制器进入下一状态
```

行为控制器输出结构至少包含：

```text
actionId
targetAnchor
movement
followUpState
optionalMessageKey
```

短文案使用本地受控文案表，根据动作和页面选择，不调用 AI 临时生成。

## 10. 性能策略

- 首屏只加载当前页面所需的待机、走路和一个常用自主动作。
- 其他动作在页面稳定后按需预加载。
- 不在 App 启动阶段加载全部动作。
- Web 精灵图只加载和解码一次。
- Android 限制同时驻留内存的动作帧集合。
- 页面离开、App 进入后台或组件卸载时清理计时器和动画。
- 低性能 Android 设备允许降低帧率和预加载数量，不改变行为规则。

## 11. 降级与错误处理

- 单个动作加载失败：回到当前静止姿势。
- 走路动作失败：直接出现在目标落点。
- 米露全部素材失败：回退到现有 `PetPlaceholder`。
- 开启“减少动态效果”：米露不走动，只在默认落点显示静止姿势；必要反馈使用短文案。
- 行为系统异常不能阻塞聊天、信箱、片场和设置功能。
- 动作失败只记录开发日志，不向普通用户显示技术错误。

## 12. 测试与验收

### 12.1 功能验收

- 五类页面都有明确安全落点。
- 米露不遮挡主要内容、输入区、导航和关键操作。
- 10 个动作均能在 Web 和 Android 完整播放。
- 页面进入时米露自然走入，且页面无需等待动画。
- 轻触、成功、失败、空闲和自主动作符合优先级规则。
- 连续轻触不会堆积动作或文案。

### 12.2 视觉验收

- 动作之间没有明显跳位。
- 无黑边、绿边、透明残影、裁切和闪烁。
- 米露在所有动作中保持同一角色形象和比例。
- 各页面显示尺寸和位置符合页面信息层级。

### 12.3 性能验收

- Web 动画期间不发生逐帧 React 状态更新。
- Android 不同时解码或常驻全部动作资源。
- 连续运行 30 分钟后，计时器、图片缓存和内存没有持续增长。
- 页面反复切换后不存在重复计时器或后台动画。

### 12.4 降级验收

- 系统减少动态效果开启后只显示静止米露。
- App 前后台切换时动画和计时器正确暂停、恢复。
- 单个动作和全部素材加载失败时均能安全回退。
- 米露异常不影响任何主要业务功能。

## 13. 后续阶段

第一阶段稳定后可独立规划：

- iOS 适配。
- 米露拖拽和落点吸附。
- 隐性关系阶段与动作解锁。
- 更多页面专属动作。
- 更复杂的跨页面连续移动。
- 在严格受控的情绪标签范围内接入 AI 动作建议。
