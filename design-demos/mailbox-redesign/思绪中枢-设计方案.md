# 喵灵 · 思绪中枢设计方案

> 配套原型：`design-demos/mailbox-redesign/solution.html`（四屏 + 双向信息流，双击可开）
> 状态：产品方向讨论稿，待确认后按阶段落地。

## 一、要解决什么

现状的问题，不是「不会整理」，而是「整理完没归处、入口太窄、喵灵太被动」：

1. **分流能力其实已经有了，但结果各奔东西**
   `backend/app/services/memory/dump_ingest.py` 已用 LangGraph extractor 把一段话自动分类成
   **待办 / 小结 / 灵感 / 情绪 / 片段**。但前端去向分散：
   - 待办 → 信箱「今日待启」
   - 情绪 → 信箱「三日寄存」
   - 片段 → 片场「待确认片段」→ 3D 场景
   - **灵感 / 小结 → 没有专门浏览界面**，藏在设置里的记忆管理

   用户说完那一刻看到一张回执统计卡，之后想知道「我说的话被整理成了什么」，
   得跑四个地方找。**整理有了，归档的「归处」是散的。**

2. **入口限在「睡前倾倒」**，不符合「随时想到就说」。

3. **喵灵不能只被动等你开口**——它该主动来信、提醒、邀请，才像活的陪伴。

## 二、方案一句话

> **你只管对喵灵说**，它自动分清这是「想法 / 想重演的过去 / 未来的事」，各归其位；
> **喵灵也会主动来**——来信、提醒、场景邀请，不让你一直等。

## 三、双向信息流

### 3.1 用户 → 喵灵（主动说）

统一入口「对喵灵说」（语音 / 文字，不分睡前随时），自动分流：

| 你说的内容 | 喵灵做什么 | 去处 |
|---|---|---|
| 想法 / 零碎 | 整理归档，让它变清晰 | 「我的思绪 · 想法」 |
| 过去难放下 / 想经历的场景 | 生成可视化 3D 场景，可重演 | 「片场」/「我的思绪 · 场景」 |
| 未来的事 | 整理成待办，到时提醒 | 「我的思绪 · 待办」 |

### 3.2 喵灵 → 用户（主动来）

| 形态 | 内容 |
|---|---|
| 来信 | 问候、音乐 / 书籍推荐、关系回访（现有来信系统） |
| 提醒 | 待办到期、次日接回昨夜思绪 |
| 场景邀请 | 日常对话中静默生成的候选片段，确认后进入重演（现有机制） |

## 四、信息架构

底部 tab 保持：**陪伴 / 信箱 / 片场 / 我的**

- **信箱** = 两块：
  - **桌宠来信**：喵灵主动写给你的（信封 → 信纸）
  - **我的思绪**：你告诉喵灵的整理结果，按 **想法 / 场景 / 待办** 分组回看
- **片场**：3D 场景的体验入口（重演过去）
- 原来的「今日待启 / 三日寄存 / 长久珍藏」全部收进「我的思绪」，不再平铺。

## 五、界面组成（对应 solution.html 四屏）

| 屏 | 角色 | 说明 |
|---|---|---|
| 1 · 对喵灵说 | 统一入口 | 大麦克风 + 分流提示（想法→清晰 / 过去→3D / 未来→待办） |
| 2 · 我的思绪 | 统一视图 | 所有整理结果集中一处，顶部筛选：全部 / 想法 / 场景 / 待办 |
| 3 · 桌宠来信 | 喵灵主动 | 信封 → 信纸；底部标出喵灵还会主动做哪些事 |
| 4 · 整理后的样子 | 归档变清晰 | 一句零碎的话 → 被拆成「想重演的过去」+「待办」，各归其位 |

## 六、对应已有能力（不重造）

| 本方案需要的 | 已有 | 缺的 |
|---|---|---|
| 自动分类 | 已有 · extractor（待办/小结/灵感/情绪/片段） | — |
| 场景生成 + 重演 | 已有 · scene 候选片段 → 3D | — |
| 来信系统 | 已有 · mailbox letters | — |
| 待办 | 已有 · mailbox todos | — |
| 想法/灵感的浏览 | ⚠️ 仅 api listIdeas | ❌ 无专门界面 |
| 统一入口 | ❌ VoiceCall/Dump/对话/造场景 四个口子 | ❌ 需整合 |
| 统一视图 | ❌ 结果散落 | ❌ 需做「我的思绪」 |

## 七、落地路径（分阶段）

- **阶段一 · 信箱重构**：信箱拆成「来信 + 思绪」两块（已有原型），把待办/寄存/珍藏收进思绪。当前进行中。
- **阶段二 · 统一入口**：整合 VoiceCall / Dump / 场景创建的语音入口为「对喵灵说」，都走同一套分流。
- **阶段三 · 想法归档**：做「想法/灵感」的浏览与整理界面（现在最缺的一块）。
- **阶段四 · 主动强化**：待办到期提醒、次日接回推送、来信主动节奏调优。

## 八、待讨论

1. **分类结果要不要先经用户确认？** 现在只有「片段→场景」走确认制（候选次日提醒）。灵感 / 待办是自动落账。要不要统一成「整理完先给你看一眼，确认才归档」？——这影响「对喵灵说」之后的流程是「直接归档」还是「先展示整理结果」。
2. **「想法」的形态**：卡片时间线（简单回看）还是可编辑的整理稿（像笔记）？
3. **自动分流误判怎么办**：给用户「撤销归档 / 改个分类」的入口（原型屏 4 已示意）。
4. **来信与思绪的比重**：用户主动说的（思绪）和喵灵主动来的（来信），在信箱里谁更主位？
