方案 A · SCENE CREATE · 新场景搭建（剧本生成）

沉浸剧场幕布式 · 分幕引导，一步步来

把整个搭建流程当作一场开演前的幕间引导：界面不再叠在别的页面上，而是一个独立的「剧场」。每一步是一幕—— 第一幕 · 讲述（入口与叙述采集）、第二幕 · 回顾（摘要确认）、第三幕 · 定妆（角色设定）——一次只呈现一个焦点， 进度表达为「第几幕」而非百分比，每屏顶部的小幕檐与幕位灯是贯穿的剧场签名。 生成等待被设计为「幕间 · 候场」：帷幕合上、灯光调暗成暖墨色的静谧画面，一束脚灯呼吸微光， 候场旁白每几秒缓缓轮换（「后台正在布景」「角色正在就位」），底部用三盏「备场灯」表达真实进度（誊写剧本 → 布置场景 → 角色候场）， 并明确告诉用户「不用守着」——支持切到后台，开演时由喵灵通知。60-90 秒的等待于是成为演出前的安静期待，而不是一根加载条。

进度怎么表达
全程没有百分比。幕内用「第一幕 / 第二幕 / 第三幕」幕位灯；候场用三盏「备场灯」对应后端真实在做的三件事（誊写剧本 → 布置场景 → 角色候场），做完一盏亮一盏，最后一盏呼吸闪烁表示「进行中」。
旁白怎么轮换
候场旁白每 6-8 秒淡入淡出轮换一条：「后台正在布景」「角色正在就位」「灯光师在调最后一束光」「道具组在摆最后一张桌子」。轮换有终态——最后一条停住，避免显得像卡死循环。
视觉怎么呼吸
暗场不是纯黑，是暖墨色（ink 的纵深变体）。帷幕有极缓的摆动（9s），脚灯光晕与光球以 4.2s 周期呼吸——接近一次深呼吸的节奏，克制动效，支持 reduced motion 降级为静态。
可以不等吗
可以。「切到后台等待」把等待交给系统，开演时以通知唤回；文案明确说「不用守着」。与现状的粗糙覆盖层（呼吸光环 + 扫光进度条 + 绝对定位盖住旧界面）相比，等待从「被挡住的加载」变成「被邀请的候场」。
