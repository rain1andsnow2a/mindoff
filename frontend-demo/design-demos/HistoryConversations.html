最有仪式感 交互：宠物名字旁的「往日」胶囊 → 全屏手帐页，按日期分组，每段会话是一张带引文摘要的卡片，点开回到那天的完整聊天。 优点：把「历史」做成了「回顾」，最贴「思绪托管」的气质；摘要卡片本身就有翻阅价值。 顾虑：摘要不等于原始列表（标题/引文需要生成规则）；只想快速续聊时路径最长。
怎么选：三个方案不互斥——B 的「首页接着聊」可以作为默认体验，A 的抽屉或 C 的手帐作为「更早历史」的承载。 后端 GET /api/v1/conversations（列表）与 GET /api/v1/conversations/{id}（消息）已实现，前端 API 封装（listConversations / getConversation）也已存在，三个方案都只是 UI 层的工作。
